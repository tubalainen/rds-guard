## A comment in .env is no value; the satellite sends at once after an outage

Found by an end-to-end run of the real images with a simulated Airspy (tools/e2e).

- **A comment where a value goes in `.env` is taken as empty.** Docker Compose reads `KEY=        # comment` as the value "# comment". The example `.env` files had such lines, so `NODE_NAME`, `NODE_LOCATION`, `TRANSCRIPTION_MODEL` and `ANTHROPIC_API_KEY` got the comment as their value. The most serious effect: the local transcription fallback tried to load a model named after the comment and failed. The log showed `fallback=local # empty = bundled KB-Whisper …`. If ElevenLabs failed, nothing was transcribed. Both the satellite and the aggregator now take such a value as empty, and say at start which keys it applied to. The example files put those comments on lines of their own.
- **The satellite sends what it has queued as soon as the aggregator is back.** After an outage the queues could wait out their backoff, up to 5 minutes, although the heartbeat already got through. An announcement or a VMA made while the aggregator was down could arrive minutes late.
- **A blank PS is no station name.** The log no longer says `Locked on to  (PI …)` before the name is complete.
- **tools/e2e**: a synthetic FM signal with RDS, stand-ins for the Airspy tools and the scenarios. See tools/e2e/README.md.

Update with `docker compose pull && docker compose up -d`. Then check the log for `In .env a comment stood where the value goes`. If the line is there, move those comments in your `.env` to lines of their own.
