## Join by approval, and one broadcast is one event

The second step towards a satellite that only receives and an aggregator that does everything else ([plan](../plans/satellit-aggregator.md)).

- **A satellite asks to join.** It needs only the aggregator's address (`AGGREGATOR_URL`, or `UPLINK_URL` as before). Without a token it makes its own, keeps it, and asks to join; it shows up under **Admin → Noder → Väntar på godkännande** with its stations, suggested place and a code like `K7Q-3PD`, which its log shows too. **Godkänn**, **Avvisa**, or **Ersätt befintlig nod** (keeps that node's history). From the command line: `python3 -m aggregator.nodes pending | approve <code> | reject <code>`. Until it is approved the satellite records as usual and queues everything.
- **`JOIN_KEY`:** the same secret on a satellite and the aggregator approves the join at once. In the shared `.env` of `docker-compose.yml`, that is all a new installation needs: `echo "JOIN_KEY=$(openssl rand -hex 16)" >> .env`.
- **One broadcast heard by several satellites (or receivers) is one event:** transcribed once (the longest recording), alerted and pushed once. The event shows who heard it (*Hörd av*), with each node's own recording. A node that goes silent mid-broadcast does not hold the alert, removing a node keeps what others heard, and push rules limited to a node match every broadcast it heard. The MQTT alert gains `nodes`.
- **The satellite reports a new broadcast at once even while a recording uploads:** events and audio go in two queues, a recording always after its event, and a retry wait is cut short by new work. Unsent items are kept for 7 days (`UPLINK_MAX_AGE_HOURS=168`).
- **`python3 -m aggregator.retranscribe`:** the v0.9.1 tool for the aggregator's archive (same flags, plus `--node`).

## Upgrading

Satellites and aggregators speak protocol 2 now and must be updated **together**: an aggregator answers a v0.10 satellite with "update needed" (its data stays queued, nothing is lost), and a v0.11 satellite gets the same from a v0.10 aggregator.

**Satellite and aggregator on one host (docker01):** nothing to change; the `UPLINK_TOKEN` you have keeps working.

```bash
docker compose pull && docker compose up -d
```

Existing events become broadcasts with one reception each at the first start.

**Friends' satellites:** they update with `docker compose pull && docker compose up -d`. Their tokens keep working. New satellites need only `AGGREGATOR_URL`, `NODE_NAME` and `NODE_LOCATION`; approve them in Admin.
