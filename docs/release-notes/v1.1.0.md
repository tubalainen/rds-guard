## The radio is set in receivers.yml only; a satellite can report to several aggregators

### Radio only in `rds-data/receivers.yml` (#106)

- **One place for the radio.** `FM_FREQUENCY`, `FM_FREQUENCIES` and `RTL_DEVICE_SERIAL` in `.env` are not used any more. Every receiver is listed in `rds-data/receivers.yml` with its serial number, which is always required, and its frequencies.
- **A new satellite writes the file itself.** The file lists the connected receivers with their real serial numbers, commented out, plus an RTL-SDR and an Airspy example. Remove the `#` at the start of your receiver's lines and set the frequency. The satellite picks up the file within a minute, without a restart. It no longer listens to 103.5 MHz by default.
- **An existing satellite moves on its own.** On the first start of v1.1.0, `FM_FREQUENCY` / `FM_FREQUENCIES` are written once to `rds-data/receivers.yml`, with `RTL_DEVICE_SERIAL` or the single connected dongle, and the satellite keeps running. An existing `receivers.yml` is never overwritten.
- **New `.env.satellite.example`** with only the satellite's settings, for a satellite on its own (`docker-compose.satellite.yml`).

### `ALSO_REPORT_TO`: several aggregators (#106)

- A satellite can report to more aggregators than its own, e.g. a friend's: `ALSO_REPORT_TO=https://rds.example.com` (comma-separated). `AGGREGATOR_URL` stays your own aggregator.
- Each aggregator has:
  - **its own queue**, so one that is down never holds up the other;
  - **its own identity:** its own token, and its own join code in the log. That aggregator's owner approves it.
- **Only your own aggregator** gets `JOIN_KEY` and `UPLINK_TOKEN`, and only it can recalibrate the receivers.
- A recording is kept on the satellite until every aggregator has it, or until `UPLINK_MAX_AGE_HOURS` (7 days) has passed. That limit now also applies while a satellite waits for approval. Before, a satellite that was never approved kept everything indefinitely.

### Node card: what is on air (#112)

- **Each station on the node card shows what it is sending now:** its RadioText and programme type, e.g. "Sportextra med världscupen i skidor · Sport", in full. A station that has been silent for a minute shows no old text.
- **The status report (heartbeat) is sent every 10 seconds** instead of 30 (`UPLINK_HEARTBEAT_SEC`).

### How to update

```bash
docker compose pull && docker compose up -d
```

Both images have changed: the satellite (`ghcr.io/tubalainen/rds-guard`) and the aggregator (`ghcr.io/tubalainen/rds-guard-aggregator`). The uplink protocol is still version 2.

After the first start, check that `rds-data/receivers.yml` exists:

```bash
docker compose logs rds-guard | grep -i "receivers.yml"
cat rds-data/receivers.yml
```

Then remove `FM_FREQUENCY`, `FM_FREQUENCIES` and `RTL_DEVICE_SERIAL` from `.env`. The log reminds you while they are still there.

If the satellite has several dongles and no `receivers.yml` or `RTL_DEVICE_SERIAL`, it writes the template and waits. In that case, fill in `rds-data/receivers.yml`. The compose files have only changed in their comments.
