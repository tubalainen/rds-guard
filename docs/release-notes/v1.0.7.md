## Does the dongle really receive? A check at every start

- **A dongle check, about 5 seconds after each receiver starts.** It looks at the first seconds the dongle gives and writes one line in the log:
  - `dongle check: OK: …, 2.39 MS/s, level −23 dBFS, 103.5M pilot 50 dB; heard 103.5M`: data comes at the full rate, and the station is heard.
  - `no FM station heard on 102.8M, 103.5M at gain 8.7 …`: the dongle runs, but no station rises above the noise. This is a warning, shown on the node card. The calibration still tries every gain.
  - `too little data from the dongle (x of y MS/s)` or `the dongle's samples do not change`: an error. The receiver stops and is started again a little later. Between half and 80 % of the rate is only a warning (USB, or a busy computer).
  - It works the same way for an Airspy.
- **`iq_side.py` draws no conclusions from noise.** With less than 10 dB between the station's side and the other side, it now says `no station here`. In earlier versions it gave `normal I/Q` and even "the sign is WRONG" for a dongle that heard nothing at all.

Update with `docker compose pull && docker compose up -d`. `iq_side.py` is in the image (since v1.0.5). With the satellite stopped:

```bash
docker compose run --rm --no-deps rds-guard python3 iq_side.py 103.5M --serial rds-guard
```
