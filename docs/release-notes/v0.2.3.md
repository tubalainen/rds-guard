## See in the log that ElevenLabs works

At startup the container now checks the ElevenLabs API key (an account lookup, no credits used) and logs the result, so `docker compose logs rds-guard | grep -i elevenlabs` shows whether transcription goes through ElevenLabs:

```
ElevenLabs: connected and authenticated (plan starter, 20 264 of 90 000 credits used) — transcribing with scribe_v3, fallback local
ElevenLabs: authentication failed (HTTP 401: invalid_api_key) — check ELEVENLABS_API_KEY; clips will be transcribed locally (…)
ElevenLabs: could not reach api.elevenlabs.io (…) — clips will be transcribed locally (…) until it answers
ElevenLabs: no ELEVENLABS_API_KEY set — transcribing locally instead
```

- Each transcription log line names the engine that served it, e.g. `via ElevenLabs scribe_v3` or `via local … (fallback)`.
- A warning is logged when 90 % of the period's ElevenLabs credits are used.
- The same applies to the aggregator (`docker compose logs aggregator`).

## Upgrading from v0.2.2

No changes are needed: pull the new image and restart (`docker compose pull && docker compose up -d`).

## Upgrading from an older version

Follow the v0.2.2 release notes first (ElevenLabs became the default engine), and for v0.1.3 README → *Operations → Upgrading from v0.1.3 to v0.2.x*.
