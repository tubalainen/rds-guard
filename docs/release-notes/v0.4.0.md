## A new web UI: archive, search and push rules

The web UI is rebuilt around the history of what your receiver has heard. It is in Swedish, works on phones and desktops, and is the same on satellites and the aggregator.

- **Arkiv** — a calendar over the stored days (colour = number of messages, red ring = VMA) and the chosen day's messages with audio, transcription and whether a push was sent. Figures for the period at the top.
- **Sök** — search in RadioText and transcriptions, filtered by type, period, station and (aggregator) node. *Bevaka* turns a search into a push rule.
- **Händelse** — one event: audio, full transcription, RadioText, pushes and details. Push messages link here.
- **Aviseringar** — push rules, the MQTT connection and the latest messages sent.
- **Debug** — the old console, now with the receiver status (PI, PTY, TP/TA, RadioText, decode rate, pipeline, uplink). Linked from the footer.
- **New audio player** — [wavesurfer.js](https://wavesurfer.xyz/) with a waveform you can click in, playback speed and download. Bundled, no CDN.

## Push notifications over MQTT

Rules decide which events become a push message on `rds/notify/<topic>` (`rds-aggregator/notify/<topic>` on the aggregator), ready for Home Assistant, Node-RED or similar to send on to a phone. A rule reads like a sentence: *when* a traffic message and/or VMA is sent on *these stations*, *and* the text mentions *these words*, *on these days* and *between these times*, *send* to this topic with this priority. Every change is tried against the stored history right away, and *Skicka test* sends a made-up message.

- Traffic is checked when the transcription is ready, so keywords also match what was said. VMA is pushed as soon as the broadcast starts.
- The message has `title`, `message`, `priority`, `matched_keywords`, `station` and, with `WEB_UI_URL` set, `url` and `audio_url`. See *Push notifications* in the README, including a Home Assistant example.
- **New installations and upgrades get two rules:** **VMA** (`notify/vma`, critical) and **Trafik** (`notify/trafik`, every traffic message). With MQTT on, the Trafik rule therefore sends a message for every traffic announcement; change or remove it under *Aviseringar*. `rds/alert` is unchanged.

### New settings (`.env`, satellite and aggregator)

| Variable | |
|---|---|
| `WEB_UI_URL` | Optional. Address of the web UI, e.g. `https://rds.example.se` (aggregator: its LAN address). Push messages then link to the event and its audio |
| `NOTIFY_TIMEZONE` | Default `Europe/Stockholm`: time zone for the days and times in push rules |

### API

`/events` takes `q`, `from`, `to` and `pi`. New: `/events/{id}` (satellite), `/calendar` and `/notify/*` (rules, preview, test, log). Writes to `/notify` must be JSON and same-origin. The aggregator's Content-Security-Policy now allows `blob:` media and inline styles, for the audio player.

## Upgrading

Satellite and aggregator: `docker compose pull && docker compose up -d`. The database gets two new tables by itself; nothing else to do.
