## Reading mixed traffic messages

A traffic announcement is seldom one incident at one place. It mixes new incidents, updates of ones already reported, reminders ("fortfarande avstängt", "som jag nämnde"), "open again", and warnings for a whole area ("mycket halt på många vägar"). RDS Guard now tells these apart.

- **Each part of a message has a kind**: new, update, repeat, cleared or area warning, with the words of the message it is based on. The server decides what a kind may change: a repeat counts as a mention but does not change the description or the status.
- **Messages about the same incident are linked better.** Known incidents from the last 36 hours (was 12) are passed on with what was said last about each, so "samma som i går" can be linked. A stretch of the same road ("E45 mellan Säffle och Grums") joins a precise incident on it, and road numbers like "E45an" are read. On 61 labelled real messages the rules engine now links 98 % of the pairs that belong together (was 72 %).
- **The right one of several places with one name.** Claude gets the real places as numbered ids with where they lie ("Stolpen (plats vid väg, i Ölme)", "Stolpen (gård, 3 km SO om Storfors)") and answers with ids.
- **Area warnings are no longer pins.** Slippery roads around Sunne no longer appear as an incident at Sunne. They are recognised; storing and showing them comes in the next release.
- Kind and words are stored per broadcast, for the coming timeline per incident.

## Places added by hand

`geodata/places-local.tsv` holds places the traffic desk names that OpenStreetMap lacks, or the one of several same-named places that is meant. A name there replaces OpenStreetMap entries of the same name within 5 km and wins over the others. First entry: Stolpen at Ölme on E18.

## Measuring placement

`tools/eval_geolocation.py` scores the engines against a labelled set of real messages (`tests/fixtures/geo_corpus.json`, 61 messages from P4 Värmland): incidents found, how precisely, places without a match, area warnings, the kind, and how well messages about one incident are linked.

```bash
docker compose exec rds-guard python3 /app/tools/eval_geolocation.py                  # rules engine, free
docker compose exec rds-guard python3 /app/tools/eval_geolocation.py --engine claude  # about 1 kr for the set
python3 tools/eval_geolocation.py --stored events.json   # score what an installation stored, free
```

## Cost

With `ANTHROPIC_API_KEY` the request to Claude is somewhat larger (places with their location, 36 hours of incidents): about 1–2 öre per message with Claude Haiku.

## Upgrading from v0.6.x

`docker compose pull && docker compose up -d`. The database gets the new columns by itself. Incidents stored earlier keep working; they have no kind or words per broadcast.
