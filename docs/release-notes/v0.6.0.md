## Trafikverket's traffic deviations (first part)

RDS Guard can now keep a copy of Trafikverket's own traffic information near the receiver: accidents, obstacles, restrictions, traffic messages and important traffic information, each with an exact position (often the affected stretch of road), the direction, how much traffic is affected, and the text Trafikverket updates while the incident lasts ("Bärgning pågår", a new expected end time, removed). Road works and ferries are left out.

This is the groundwork. The data is collected and served by the API; matching it to the radio messages (an exact pin and the affected road on the map), a map layer for incidents that were never on the radio, a timeline and push messages for the updates come in the next releases.

- **Optional and free.** Set `TRAFIKVERKET_API_KEY` (a free key from [Trafikverket's open API](https://data.trafikverket.se/)). There is no cost per message. Without a key nothing changes.
- **Satellite:** watches 150 km around `NODE_LOCATION` (needed). **Aggregator:** watches around every node that reports a location.
- **Only changes are fetched.** Every minute RDS Guard asks for what changed since the last call (`changeid`), so the calls are small. Everything is read again every six hours, and when the area changes, so nothing missed stays behind.
- **Every version is kept**, with the fields that changed, for the coming timeline. Removed and suspended deviations are marked. They are deleted with the events (`EVENT_RETENTION_DAYS`).
- Errors (no network, a wrong key) are logged and retried with a growing pause; the rest of RDS Guard is not affected.

### Check that it works

```bash
docker compose logs rds-guard | grep -i trafikverket
curl -s http://localhost:8022/api/status | python3 -c 'import json,sys; print(json.load(sys.stdin)["trafikverket"])'
curl -s 'http://localhost:8022/api/trafikverket?hours=24'
```

The status shows `last_ok`, `active` (the number of current deviations) and, when something is wrong, `last_error`.

## New settings (`.env`)

| Variable | Where | |
|---|---|---|
| `TRAFIKVERKET_API_KEY` | satellite, aggregator | Optional, free. Empty = off |
| `TRAFIKVERKET_RADIUS_KM` | satellite, aggregator | Default `150` |
| `TRAFIKVERKET_POLL_SEC` | satellite, aggregator | Default `60` (at least 30) |

## New API

| Endpoint | |
|---|---|
| `GET /api/trafikverket` (satellite), `GET /api/v1/trafikverket` (aggregator) | Current deviations and those changed in the last `hours` (default 12), each with its versions |
| `/api/status`, `/api/v1/status` | New field `trafikverket`: whether the feed is on, last successful call, last error, number of active deviations |

## Upgrading from v0.5.x

1. Optional: add `TRAFIKVERKET_API_KEY=<key>` to `.env` (satellite: `NODE_LOCATION` must be set).
2. `docker compose pull && docker compose up -d`. The database gets the new tables by itself.
