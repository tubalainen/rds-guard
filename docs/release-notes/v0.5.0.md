## A map of what the traffic messages are about

The new **Karta** page shows where the traffic messages of the last 12 hours are, read from what the announcer said ("E18 i Karlstad, i höjd med Bergviksmotet, i riktning mot Grums"). Satellites and the aggregator both have it.

- **A pin per incident**, fading as it gets older and gone after 12 hours. Several messages about the same incident update one pin; a later "öppet igen" turns it grey.
- **A red circle** around the pin: the larger, the less certain the place. About ±500 m at a junction, half the distance for "mellan A och B", ±5 km for a town alone. Places less certain than ±25 km are not shown.
- **An arrow** for the direction of traffic affected, a double arrow when both directions are, none when the message does not say.
- Event cards in *Arkiv* and *Sök* get a place label that opens the map, and each event page has a small map.
- The **aggregator** shows all nodes' incidents on one map, with which nodes heard them.

### Local first; ElevenLabs and Claude are options

Everything runs locally, without a GPU or paid services: a rules engine reads the message and a place-name registry finds the coordinates. The registry is built from OpenStreetMap (ODbL) and bundled in the images, so nothing is downloaded while RDS Guard runs. Misheard names are corrected by Swedish sound-alike matching ("Skatscher" → Skattkärr, "Kallskoga" → Karlskoga). Paid services are options that make it better:

- **Claude** (`ANTHROPIC_API_KEY`, `GEO_ENGINE=claude`, default model Claude Haiku, about 1–3 öre per message) reads the message and also corrects misheard words in the whole transcription. Corrected texts get a **Rättad** tag in the web UI; tap it to switch between the corrected and the original text. Claude only names places; the coordinates always come from the local registry. If the call fails, the rules engine places the message instead.
- **ElevenLabs** now also gets the place names around your receiver as keyterms (`TRANSCRIPTION_PLACE_NAMES`, on by default, about 20 % more per clip). Local Whisper gets the names most often mentioned before in its prompt.

On 40 real P4 Värmland messages the rules engine placed 22 of 23 incidents right. Those are the messages the rules were tuned on, so expect less on new ones. To measure both engines on your own messages:

```bash
docker compose exec rds-guard python3 /app/tools/measure_geolocation.py
```

MQTT alerts (`rds/alert`, `rds-aggregator/alert`) carry two new fields: `transcribed_text_corrected` and `locations`. Push rules also match the corrected text.

### A satellite can leave all processing to the aggregator

`LOCAL_PROCESSING=false` makes a satellite only record and send its raw recordings: no transcription, no map, no AI or cloud calls. The aggregator transcribes and maps everything either way. The default (`true`) keeps everything as before. If both the satellite and the aggregator have paid keys, both pay for the same message. A standalone installation always processes its own recordings. See *Who processes the recordings* in the README.

## New settings (`.env`)

| Variable | Where | |
|---|---|---|
| `NODE_LOCATION` | satellite | Where the receiver is, as `Ort, Län`, e.g. `Karlstad, Värmlands län`. Needed for the map; reported to the aggregator |
| `GEO_ENGINE` | satellite, aggregator | `claude` (default; runs as `rules` without a key), `rules` or `none` |
| `ANTHROPIC_API_KEY` | satellite, aggregator | Optional, for the Claude engine |
| `CLAUDE_MODEL`, `CLAUDE_TIMEOUT` | satellite, aggregator | Default `claude-haiku-5-5` and `60` |
| `TRANSCRIPTION_PLACE_NAMES` | satellite, aggregator | Default `true`: local place names for ElevenLabs and Whisper |
| `LOCAL_PROCESSING` | satellite | Default `true`; `false` = raw recordings to the aggregator only |

## Upgrading from v0.4.3

1. Add to `.env` on the satellite:
   ```env
   NODE_LOCATION=Karlstad, Värmlands län
   # Optional: ANTHROPIC_API_KEY=<key>
   ```
2. `docker compose pull && docker compose up -d`. The databases get the new columns and tables by themselves.
3. On the aggregator the map places a node's messages once that node runs v0.5.0 and has `NODE_LOCATION` set. Until then its messages are stored as before, without a place.
