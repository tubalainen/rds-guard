## Upgrading from v0.2.0

No changes are needed: pull the new image and restart (`docker compose pull && docker compose up -d`).

## Upgrading from v0.1.3

v0.2.x is a drop-in upgrade for a standalone install. Satellite mode is optional and **off by default**: if you don't set `UPLINK_URL`, RDS Guard runs exactly as before, and nothing is sent anywhere. You don't need to change `.env` or `docker-compose.yml`, and your existing events, audio and transcriptions are kept.

### Standalone (no aggregator), which covers most users

1. **Back up your data (recommended).** Stop the container and copy the data folder:
   ```bash
   docker compose down
   cp -a rds-data rds-data.backup-0.1.3
   ```
2. **Pull the new image and start again:**
   ```bash
   docker compose pull
   docker compose up -d
   ```
   If you build locally (`build: .`), run `git pull` and then `docker compose up -d --build` instead.
3. **Check the log:**
   ```bash
   docker compose logs -f rds-guard
   ```
   You should see `Mode: standalone (no uplink)`. The web UI footer shows the new version.

That's all. On first start the database in `rds-data/events.db` is migrated automatically. A new `event_uid` column and an empty `outbox` table are added, and existing rows are not changed. The outbox is only used in satellite mode.

**Pinning a version:** `ghcr.io/tubalainen/rds-guard:latest` follows `master`. To stay on a release, set the image to `ghcr.io/tubalainen/rds-guard:0.2.1` (or `:0.2` to get 0.2.x patch releases).

**Rolling back:** set the image to `ghcr.io/tubalainen/rds-guard:0.1.3`, and restore `rds-data.backup-0.1.3` if you want the database exactly as it was. v0.1.3 ignores the added column and table, so it also runs on the migrated database.

### Optional: join an aggregator (satellite mode)

Ask the aggregator's owner for an address and a node token, then add these lines to `.env` and restart with `docker compose up -d`:

```env
UPLINK_URL=https://rds.example.com
UPLINK_TOKEN=<node token>
NODE_NAME=<your name or place>
# UPLINK_HEARTBEAT_SEC=30
# UPLINK_MAX_AGE_HOURS=72
```

New events, their audio and a status heartbeat are sent to the aggregator. Transcriptions are not sent. Events recorded before the upgrade are not sent either. If `UPLINK_URL` is set without `UPLINK_TOKEN`, or doesn't start with `http://` or `https://`, the container stops with an error. See the README's satellite guide and `docs/uplink-protocol.md` for details. Running your own aggregator is a separate service (`ghcr.io/tubalainen/rds-guard-aggregator`), described in `aggregator/`.
