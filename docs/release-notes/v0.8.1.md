## Fewer incidents merged by mistake

Measured on the 61 labelled messages, Claude with v0.7 found 95 % of the incidents (was 84 % before v0.7) with 6 places without a match (was 14), but merged 10 pairs that are different incidents. Nearly all came from one rule: two precise places less than 2 km apart became one incident, even when one message named both ("krock vid Klaramotet … kökrock vid Våxnäsmotet").

- Two parts of the same message are never merged into one incident.
- When Claude, having seen the known incidents, says a part is new, it joins a known incident only if the place has the same name.
- A town named on a stretch ("mellan Väse och Karlstad, vid Skattkärr") is used instead of the middle of the stretch when its circle is smaller.

## Measuring

- `tools/eval_geolocation.py --engine claude` prints a line per message as it goes (message, tokens, errors).
- `--save-claude claude.json` keeps Claude's answers (written after every message); `--replay claude.json` runs them again through the server's logic without calling Claude, for free.

```bash
docker compose exec rds-guard python3 /app/tools/eval_geolocation.py --engine claude --save-claude /data/claude.json
```
