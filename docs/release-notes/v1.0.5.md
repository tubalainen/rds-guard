## Airspy Mini and Airspy R2

- **The satellite can use an Airspy Mini or an Airspy R2 as a receiver**, alone or together with RTL-SDR dongles on the same host.
  - Put it in `receivers.yml` by its serial number, which is 64 bits in hex: `serial: "0x644064DC2B1C2E4F"`.
  - `python3 -m dongles` lists it. An Airspy the satellite is running cannot be listed, so stop the satellite first.
  - The satellite sees whether it is a Mini (captured at 3 MS/s) or an R2 (2.5 MS/s). Up to 4 stations within 2 MHz, as on a dongle.
  - Decoding, recording and the aggregator work as before: the Airspy's signal is brought to the same 171 kHz multiplex as a dongle's.
- **Gain:** an Airspy is calibrated over its linearity gain, 0–21, in the same way as a dongle. It starts at 8 until the first calibration. `gain: 10` in `receivers.yml` fixes it. The node card shows the step as its gain.
- **No ppm on an Airspy:** its clock is a TCXO, so there is no ppm step, and `ppm:` is ignored for it.
- **No host preparation:** no DVB driver to blacklist. The same `/dev/bus/usb` in the compose file passes it to the container. The bias tee stays off.
- **Check I/Q once** with the satellite stopped (`normal` is what the satellite expects):
  `docker compose run --rm rds-guard python3 iq_side.py 103.5M --serial 0x…`
- **RTL-SDR dongles work exactly as before.**

This release also contains v1.0.4 (ppm measured during the gain sweep), if you have not installed it.

Update with `docker compose pull && docker compose up -d`.
