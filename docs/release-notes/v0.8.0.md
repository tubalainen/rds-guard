## Every broadcast about an incident, with its audio

An incident on the map now has a timeline: every broadcast that spoke of it, in order, with the time, what kind of message it was (**Ny**, **Uppdatering**, **Påminnelse**, **Avklarad**), the words of the broadcast it is based on, a play button and a link to the broadcast. **Spela alla** plays them one after another. Trafikverket's updates are in the same timeline, as before.

- The quote in the popup is now what the latest broadcast said about *this* incident, not the start of the message (a message often speaks of several).
- On a broadcast's page, each incident under "Plats" links to it on the map.
- New API: `GET /api/incidents/{id}` (satellite) and `GET /api/v1/incidents/{id}` (aggregator) give one incident with its timeline; `/api/incidents` has a `timeline` per incident.
- Incidents stored before v0.7.0 have no kind or words per broadcast; their timeline shows the times and the audio.

## Warnings for an area

Warnings for many roads ("mycket halt på många vägar i Värmlands län", snow, storm) are listed above the map, with a link to the message, instead of becoming a pin at some town. The same warning said again is one line. They are in `/api/incidents` as `areas`.

## Rebuild the map

**Admin → Karta → Bygg om kartan** places every stored traffic message again, oldest first, with the current model, and replaces all incidents (also Trafikverket links and area warnings). Before you confirm it says how many messages, with which engine and about what it costs (Claude: about 1.5 öre per message; the rules engine is free). Progress shows on the page and on the map.

Use it once after upgrading to get kinds, words and timelines for older messages. Incident numbers change, so links to an incident (and push messages already sent) point nowhere afterwards; links to broadcasts keep working.

## Upgrading from v0.7.x

`docker compose pull && docker compose up -d`. The database gets the new table by itself. Then, if you like, Admin → Karta → Bygg om kartan.
