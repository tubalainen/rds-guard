## The AF list in the health file; the node card shows an Airspy's gain as it is

- **Each station's AF list in `health.json`.** The AF list is the list of alternative frequencies the transmitter sends: frequencies carrying the same programme, and with method B its regional variants. It may tell P4 regions apart even when they all send the shared PI 0xE224 "P4 SR" in the evenings, at night and at weekends. The fields are `af` and `af_regional` per station. To see them:

```bash
docker compose exec rds-guard cat /data/health.json | python3 -m json.tool | grep -E '"frequency"|"pi"|"af'
```

- **The node card shows an Airspy's gain as it really is.** With LNA, Mixer and VGA set by hand, the card said "gain 8 dB (fast) · 0 ppm": a linearity step shown as dB, and a ppm an Airspy does not have. It now says "gain LNA 4, Mixer 4, VGA 5 (för hand)", or "(linjäritet 8)" when calibrated, and shows no ppm for an Airspy. An RTL-SDR shows "gain 8.7 dB" as before.

Update with `docker compose pull && docker compose up -d`.
