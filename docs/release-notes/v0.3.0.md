## Aggregator: one container behind your own reverse proxy

v0.3.0 changes only the aggregator. Satellites and standalone installations work exactly as before and need no changes.

- **One container.** The aggregator no longer starts its own nginx and `cloudflared`. Its ingest port, `8081`, serves `/api/v1/ingest/*` and nothing else, so the HTTPS reverse proxy you already run (Nginx Proxy Manager, Caddy, Traefik …) or a Cloudflare Tunnel forwards straight to it. Port `8080` (web UI, no login) stays on your LAN.
- **Data in a folder.** Database, audio and downloaded models are stored in `aggregator-data` next to `docker-compose.yml` instead of a Docker volume, so they are easy to back up and inspect.
- **File ownership.** The container starts as root only to make that folder writable, then runs as an unprivileged user (uid 10001, or `PUID` / `PGID` in `.env`) before it opens the database or listens on a port.
- **Setup guide.** The aggregator README lists every Nginx Proxy Manager and Cloudflare setting, and a `curl` check that tells you whether the proxy reaches the right port.

## Upgrading the aggregator from v0.2.x

Nodes, tokens and events are in the old Docker volume. **Copy them into the new folder before you start v0.3.0**, or the aggregator starts with an empty database and every satellite needs a new token.

```bash
cd rds-guard/aggregator
git pull
docker compose down --remove-orphans
mkdir -p aggregator-data
docker run --rm -v aggregator_aggregator-data:/from -v "$PWD/aggregator-data":/to alpine cp -a /from/. /to/
docker compose pull && docker compose up -d
```

The volume is normally called `aggregator_aggregator-data`; check with `docker volume ls`. Then point your reverse proxy or tunnel at port `8081` of the aggregator instead of nginx, and check it with `curl -i https://<your-host>/api/v1/ingest/heartbeat` (the right answer is HTTP 426). When everything works, remove the old volume with `docker volume rm aggregator_aggregator-data`.

The full steps are in `aggregator/README.md` → *Upgrading from v0.2.3 or older*.

### Changed settings (aggregator `.env`)

| Variable | |
|---|---|
| `INGEST_API_BIND` / `INGEST_API_PORT` | New, default `0.0.0.0` / `8081`: where the ingest API is published on the host |
| `PUID` / `PGID` | New, default `10001`: owner of the files in `aggregator-data` |
| `NGINX_BIND` / `NGINX_PORT`, `CLOUDFLARE_TUNNEL_TOKEN` | No longer used |

nginx also limited requests per client address. The per-node limit in the aggregator stays; to also cap requests without a valid token, add a rate limiting rule for `/api/v1/ingest/` in Cloudflare or your proxy.

## Upgrading a satellite

Nothing to do. To get the new image anyway: `docker compose pull && docker compose up -d`.
