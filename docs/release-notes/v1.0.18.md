## A single corrupted RDS group no longer sends a VMA

A VMA push goes out as soon as an emergency broadcast starts, without waiting for it to end. Until now, one RDS group saying programme type Alarm was enough to start one. On a weakly received station a single corrupted group can say exactly that. This was seen on 100.3 MHz on docker01 at about 4 groups per second. The event was then discarded as too short, but the push had already gone out. An end-to-end run of v1.0.17 with a simulated station showed `Push 'VMA'` for each such group.

- **The programme type changes only when three groups in a row agree**, the same rule v1.0.16 introduced for TA. That takes under a second. A real VMA starts from its first group, and a single stray group neither starts one nor ends one.
- **The log names an ignored group:** `PTY Alarm in 1 group(s) only, ignored`, with its group type and block error rate.
- **tools/e2e can send corrupted Alarm groups** (`corrupt_pty`). Its scenario also checks the push log, not only the event list.

Update with `docker compose pull && docker compose up -d`. Only the satellite has changed.
